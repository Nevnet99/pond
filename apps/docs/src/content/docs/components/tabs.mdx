Switch between closely related views in one place. Panel content uses named slots matching each tab `value`. Prefer separate pages or [Side nav](/components/side-nav/) when destinations are unrelated. `appearance="plain"` strips Pond visuals — you own focus paint and contrast.

```html
</pond-tabs>
```

### API

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `items` | `PondTabItem[]` | `[]` | Tab descriptors: `{ value, label, disabled? }` |
| `selected` | `string` | `''` | Selected tab `value`; falls back to first enabled item |
| `appearance` | `'default' \| 'plain'` | `'default'` | `plain` strips Pond visual CSS |

**Slots:** one named slot per tab `value` — panel content for that tab.

**CSS parts:** `root`, `tablist`, `tab`, `panels`, `panel`.

**Events:** `pond-change` — `{ detail: { value } }` when selection changes.

### Purpose

Tabs keep related panels in one view with a single selection. They are **not** for multi-step wizards ([Progress tracker](/components/progress-tracker/)) or page-level destinations ([Link](/components/link/), [Side nav](/components/side-nav/)).

### Anatomy

1. **Tab list** (`::part(tablist)`) — `role="tablist"`
2. **Tab** (`::part(tab)`) — `role="tab"` button per item
3. **Panels** (`::part(panels)` / `::part(panel)`) — active `role="tabpanel"` with a named slot

### Content guidelines

- Short, unique labels (sentence case)
- Labels name the panel, not an action (“Settings”, not “Click settings”)
- Keep panels related; if users compare content side-by-side, prefer separate regions instead of tabs

### Happy path vs plain

Default ships underline chrome and Pond focus rings. `appearance="plain"` keeps tab / tabpanel semantics and keyboard behavior — **you** own focus paint and contrast.

**Page header bottom tabs** — section a page under the title without leaving the route.

```html
<pond-page-header heading="Projects">
  <pond-tabs
    slot="bottom"
    selected="overview"
    items='[{"value":"overview","label":"Overview"},{"value":"activity","label":"Activity"}]'
  >
    <div slot="overview">…</div>
    <div slot="activity">…</div>
  </pond-tabs>
</pond-page-header>
```

**Prefer Side nav for destinations** — if each “tab” is a different app area with its own URL, use [Side nav](/components/side-nav/) (or links), not Tabs.
