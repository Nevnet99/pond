Present flat tabular data with a caption, column headers, and rows. Prefer [Dynamic table](/components/dynamic-table/) when you need client sort or pagination, and [Table tree](/components/table-tree/) when rows nest. `appearance="plain"` strips Pond chrome — you own borders and contrast.

```html
<pond-table
  caption="Team"
  columns='[{"key":"name","label":"Name"},{"key":"role","label":"Role"}]'
  rows='[{"name":"Ada","role":"Engineer"}]'
></pond-table>
```

### API

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `caption` | `string` | `''` | Table caption (strongly recommended) |
| `columns` | `{ key: string; label: string }[]` | `[]` | Header definitions (`key` maps into each row) |
| `rows` | `Record<string, string>[]` | `[]` | Row objects keyed by column `key` |
| `appearance` | `'default' \| 'plain'` | `'default'` | `plain` strips Pond visual CSS |

**Slots:** none — data is properties / JSON attributes.

**CSS parts:** `root`, `table`, `caption`, `tr`, `th`, `td`.

**Events:** none.

### Purpose

Show a simple, non-interactive grid of string cells. Not for layout, sorting, paging, selection, or nested rows.

### Anatomy

1. **Root** (`::part(root)`) — scroll container  
2. **Table** (`::part(table)`) — native `<table>`  
3. **Caption** (`::part(caption)`) — when `caption` is set  
4. **Headers / cells** (`::part(th)`, `::part(td)`) — `scope="col"` on headers

### Content guidelines

- Caption names the dataset (“Team”, “Invoices”)
- Column labels are short nouns; keep cell text scannable
- Empty datasets still need headers + caption (pair with [Empty state](/components/empty-state/) nearby when useful)

### Happy path vs plain

Default ships border, caption type, and header surface. Plain keeps native table semantics — **you** own chrome.

  caption="Assignees"
  columns='[{"key":"name","label":"Name"},{"key":"role","label":"Role"}]'

**Prefer Dynamic table** for client sort + pagination. **Prefer Table tree** for expandable nested rows. Do not use Table for page layout.
