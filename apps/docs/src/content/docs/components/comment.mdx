### API

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `author` | `string` | `''` | Visible author name |
| `meta` | `string` | `''` | Timestamp or secondary meta line |
| `avatar-initials` | `string` | `''` | Initials for default Avatar (falls back to first two of `author`) |
| `appearance` | `'default' \| 'plain'` | `'default'` | `plain` strips Pond visual CSS |

**Slots:** default — body; `avatar` — overrides default Avatar; `actions` — footer actions.

**CSS parts:** `root`, `header`, `identity`, `author`, `meta`, `body`, `actions`.

**Events:** none from Comment itself — listen on slotted actions.

### Purpose

Render a single discussion item in a feed or review. Not for nested threads (compose siblings), reactions, or an inline editor.

### Anatomy

1. **Root** (`::part(root)`) — `<article>` shell  
2. **Header** (`::part(header)`) — avatar + identity  
3. **Author / meta** (`::part(author)`, `::part(meta)`)  
4. **Body** (`::part(body)`) — default slot  
5. **Actions** (`::part(actions)`) — `actions` slot (hidden when empty)

### Content guidelines

- Author is a person or system name; meta is relative or absolute time
- Body is the comment text — keep actions labeled verbs (“Reply”, “Edit”)
- Do not nest Comment inside Comment for threads in this phase

### Happy path vs plain

Default ships border, padding, type, and Avatar. Plain keeps article structure and slots — **you** own chrome.
