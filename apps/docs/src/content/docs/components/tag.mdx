### API

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `removable` | `boolean` | `false` | Shows remove button; fires `pond-remove` |
| `appearance` | `'default' \| 'plain'` | `'default'` | `plain` strips Pond visual CSS |

**Slots:** default — tag label text.

**CSS parts:** `root`, `remove`.

**Events:** `pond-remove` — bubbles when the remove control is activated.

### Purpose

Mark metadata or a filter chip. Not for status ([Lozenge](/components/lozenge/)), navigation, or primary actions ([Button](/components/button/)).

### Anatomy

1. **Root** (`::part(root)`) — chip shell  
2. **Default slot** — label  
3. **Remove** (`::part(remove)`) — optional button when `removable`

### Content guidelines

- Keep labels short and scannable (1–2 words)
- Sentence case for multi-word labels unless they are proper nouns
- Remove must be named for AT — today the control ships as “Remove”; prefer wrapping context that includes the tag value in surrounding copy, or set a more specific name from the consumer when overriding

### Happy path vs plain

Default ships pill chrome and remove focus ring. Plain keeps remove behavior — **you** own chrome and focus paint.

**Filter chip with remove** — listen for `pond-remove` and drop the value from your filter model.

```html
<pond-tag removable id="tag-design">Design</pond-tag>
<script>
  document.getElementById('tag-design').addEventListener('pond-remove', () => {
    /* remove "Design" from filters */
  })
</script>
```

**Prefer Tag group** when laying out several related tags. **Prefer Lozenge** for status tone that is not dismissible metadata.
