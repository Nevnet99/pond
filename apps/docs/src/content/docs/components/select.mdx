Choose one or more options from a known, finite list. Prefer [Radio](/components/radio/) or [Checkbox](/components/checkbox/) when every option should stay visible. Always set a visible `label`. `appearance="plain"` strips Pond visuals — you own chrome, focus paint, and contrast.

### API

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `label` | `string` | `''` | Visible label (required for accessible use) |
| `name` | `string` | `''` | Native form name |
| `value` | `string` | `''` | Selected value (single mode) |
| `values` | `string[]` | `[]` | Selected values (`multiple`) |
| `options` | `{ value: string; label: string }[]` | `[]` | Option list (property or JSON attribute) |
| `multiple` | `boolean` | `false` | Native multi-select |
| `disabled` | `boolean` | `false` | Removes from tab order when set |
| `appearance` | `'default' \| 'plain'` | `'default'` | `plain` strips Pond visual CSS |

**Slots:** none — options come from the `options` property.

**CSS parts:** `root`, `label`, `select`.

**Events:** `pond-change` — `{ detail: { value } }` or `{ detail: { values } }` in multi mode.

### Purpose

Pick from a finite list that does not need to stay fully visible. Not for free text ([Text field](/components/text-field/)) or long searchable catalogs (build a combobox pattern later).

### Anatomy

1. **Root** (`::part(root)`)  
2. **Label** (`::part(label)`) — associated via `for`/`id`  
3. **Select** (`::part(select)`) — native `<select>` / `<option>`

### Content guidelines

- Label the control (“Size”), not the first option (“Select…”)
- Option labels are sentence case and distinct
- Prefer Radio/Checkbox groups when there are few options and comparison matters

### Happy path vs plain

Default ships label type, border, and focus ring. Plain keeps native select behavior and labeling — **you** own chrome.
