Single-line entry for names, emails, and short values. Prefer [Text area](/components/text-area/) for multi-line. Always pair with a visible `label` — never placeholder alone. `appearance="plain"` strips Pond visuals — you own chrome, focus paint, and contrast.

Listen for value changes:

```html
<pond-text-field label="Name"></pond-text-field>
<script type="module">
  document.querySelector('pond-text-field').addEventListener('pond-input', (e) => {
    console.log(e.detail.value)
  })
</script>
```

### API

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `label` | `string` | `''` | Visible label (required for accessible use) |
| `name` | `string` | `''` | Native form name |
| `value` | `string` | `''` | Current value (reflects on `pond-input`) |
| `type` | `'text' \| 'email' \| 'password' \| 'search' \| 'url' \| 'tel'` | `'text'` | Native input type |
| `placeholder` | `string` | `''` | Hint only — never the only label |
| `disabled` | `boolean` | `false` | Removes from tab order when set |
| `required` | `boolean` | `false` | Native required |
| `invalid` | `boolean` | `false` | Sets `aria-invalid` and danger chrome |
| `error-message` | `string` | `''` | Error text; linked via `aria-describedby` when `invalid` |
| `appearance` | `'default' \| 'plain'` | `'default'` | `plain` strips Pond visual CSS |

**Slots:** none — label and error are attributes.

**CSS parts:** `root`, `label`, `input`, `error`.

**Events:** `pond-input` — `{ detail: { value: string } }` on each input.

### Purpose

Collect a single line of text in a form or filter. Not for long notes ([Text area](/components/text-area/)) or choosing from a fixed list ([Select](/components/select/)).

### Anatomy

1. **Root** (`::part(root)`) — stacks label, input, error  
2. **Label** (`::part(label)`) — associated with the input via `for`/`id`  
3. **Input** (`::part(input)`) — native `<input>`  
4. **Error** (`::part(error)`) — shown when `invalid` + `error-message`

### Content guidelines

- Visible label in sentence case (“Project name”)
- Error copy says how to fix (“Enter a valid email”), not only “Invalid”
- Placeholder is a hint for format, never the label
- Keep input text at the `md` (16px) step on mobile (Pond default)

### Happy path vs plain

Default ships label type, border, danger chrome, and focus ring. `appearance="plain"` keeps label association, `aria-invalid` / `aria-describedby`, and `pond-input` — **you** own chrome.

**Labeled field + validate on submit** — keep the primary [Button](/components/button/) pressable; set `invalid` + `error-message` from your validator instead of disabling the field while the user types.

```html
<pond-stack gap="4">
  <pond-text-field label="Email" type="email"></pond-text-field>
  <pond-button type="submit">Continue</pond-button>
</pond-stack>
```

**Prefer Text area** when the answer is more than one short line.
