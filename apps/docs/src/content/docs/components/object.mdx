Generic content-type glyph (document, folder, link, image, code, person) for lists, tables, and pickers. Not an Atlassian product icon set — forks can slot custom glyphs. Prefer [Tile](/components/tile/) for labeled square cards, [Logo](/components/logo/) for brand marks, [Icon](/components/icon/) for UI chrome glyphs, and [Image](/components/image/) for photos. `appearance="plain"` strips Pond chrome — you own the glyph surface.

### API

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `type` | `'document' \| 'folder' \| 'link' \| 'image' \| 'code' \| 'person'` | `'document'` | Built-in content-type glyph |
| `size` | `'sm' \| 'md' \| 'lg'` | `'md'` | Glyph footprint |
| `label` | `string` | `''` | Accessible name (`role="img"`); unlabeled objects are decorative / `aria-hidden` |
| `appearance` | `'default' \| 'plain'` | `'default'` | `plain` strips Pond visual CSS |

**Slots:** default — optional override of the built-in glyph.

**CSS parts:** `root`, `glyph`.

**Events:** none (presentational).

### Purpose

Object marks a **content type** beside titles and rows. It is **not** a brand ([Logo](/components/logo/)), photo ([Image](/components/image/)), square picker card ([Tile](/components/tile/)), or person face ([Avatar](/components/avatar/) — use `type="person"` only as a type cue, not identity).

### Anatomy

1. **Host** — `pond-object`
2. **Surface** (`::part(root)`) — rounded glyph well
3. **Glyph** (`::part(glyph)`) — SVG or slotted override

### Content guidelines

- Set `label` when the glyph is the only name
- Leave unlabeled only when decorative beside visible text that already names the type
- Do not treat Object as Atlassian (or any vendor) product icons

### Happy path vs plain

Default ships subtle surface, size steps, and built-in paths. `appearance="plain"` unwraps — **you** own chrome; labelling rules stay.
