Client-side column sort, pagination, and optional row reorder on a flat dataset. Prefer plain [Table](/components/table/) when sorting and paging are not needed. Prefer [Table tree](/components/table-tree/) for nested rows. No remote/async data API in this phase. `appearance="plain"` strips Pond chrome — you own borders, sort chrome, and contrast.

```html
<pond-dynamic-table
  caption="People"
  page-size="5"
  columns='[{"key":"name","label":"Name"},{"key":"role","label":"Role"}]'
  rows='[{"name":"Ada","role":"Lead"}]'
></pond-dynamic-table>
```

### API

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `caption` | `string` | `''` | Table caption |
| `columns` | `{ key: string; label: string }[]` | `[]` | Sortable column headers |
| `rows` | `Record<string, string>[]` | `[]` | Client-side dataset |
| `page-size` | `number` | `5` | Rows per page |
| `page` | `number` | `1` | Current page (1-based) |
| `sort-key` | `string` | `''` | Active sort column key |
| `sort-direction` | `'asc' \| 'desc'` | `'asc'` | Sort direction |
| `reorderable` | `boolean` | `false` | Shows up/down controls; fires `pond-reorder` |
| `appearance` | `'default' \| 'plain'` | `'default'` | `plain` strips Pond visual CSS |

**Slots:** none.

**CSS parts:** `root`, `table-wrap`, `table`, `th`, `td`, `sort`, `reorder`, `pagination`.

**Events:** `pond-sort` — `{ detail: { key, direction } }`; `pond-change` — `{ detail: { page } }`; `pond-reorder` — `{ detail: { rows, from, to } }`.

### Purpose

Operate on an in-memory flat table: sort columns, page results, optionally reorder rows. Not a remote grid, selection model, or nested tree.

### Anatomy

1. **Root** (`::part(root)`) — table + pagination stack  
2. **Table** (`::part(table)`) — native table with sortable header buttons  
3. **Sort control** (`::part(sort)`) — per-column button; `aria-sort` on `<th>`  
4. **Reorder** (`::part(reorder)`) — optional up/down buttons  
5. **Pagination** (`::part(pagination)`) — composed [Pagination](/components/pagination/)

### Content guidelines

- Caption names the dataset
- Column labels match what sorting means to the user
- Keep `page-size` small enough that a page stays readable

### Happy path vs plain

Default ships borders, header surface, sort focus rings, and Pagination. Plain keeps sort/page/reorder behavior — **you** own chrome and focus paint.

```html

  page-size="10"
```

**Prefer Table** when you only need a static grid. **Prefer Table tree** when rows nest and expand. Do not treat Dynamic table as a server-driven data grid yet.
