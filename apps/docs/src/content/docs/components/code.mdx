### API

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `variant` | `'inline' \| 'block'` | `'inline'` | Inline `<code>` vs `<pre><code>` block |
| `appearance` | `'default' \| 'plain'` | `'default'` | `plain` strips Pond visual CSS |

**Slots:** default — code text / content.

**CSS parts:** `root` — the native `code` (inline) or `pre` (block) host.

**Events:** none.

### Purpose

Mark literal machine text (commands, tokens, short snippets). Not for long-form prose, syntax-colored editors, or status labels ([Lozenge](/components/lozenge/), [Tag](/components/tag/)).

### Anatomy

1. **Root** (`::part(root)`) — native `<code>` (inline) or `<pre>` wrapping `<code>` (block)  
2. **Default slot** — the snippet text

### Content guidelines

- Prefer short, copy-pasteable strings
- Keep literal casing from the source language or command
- Do not rely on color alone for meaning (no highlighter ships)

### Happy path vs plain

Default ships mono font, subtle surface, and padding. Plain keeps native `code` / `pre` semantics — **you** own chrome and contrast.
