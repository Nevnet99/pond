Overlapping layout for a stack of [Avatar](/components/avatar/) children. Layout helper only — face styling comes from Avatar. Prefer a single Avatar for one person. `appearance="plain"` strips overlap chrome — you own the stack layout.

### API

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `label` | `string` | `'Avatars'` | Accessible name for `role="group"` |
| `appearance` | `'default' \| 'plain'` | `'default'` | `plain` strips overlap chrome |

**Slots:** default — one or more `pond-avatar` children.

**CSS parts:** `root` — flex row that overlaps slotted avatars.

**Events:** none (presentational).

### Purpose

Avatar group stacks **multiple people** with overlap. It is **not** a single identity ([Avatar](/components/avatar/)) and does **not** yet ship overflow/`+N` counting — keep the set small or provide another way to list members.

### Anatomy

1. **Host** — `pond-avatar-group`
2. **Group** (`::part(root)`) — `role="group"` row
3. **Children** — slotted `pond-avatar` faces

### Content guidelines

- Set a meaningful group `label` (e.g. “Collaborators”)
- Label each Avatar with the person’s name
- Do not stack so many faces that names become impossible to discover

### Happy path vs plain

Default ships negative-margin overlap and canvas rings. `appearance="plain"` unwraps — **you** own stack layout; group naming stays.

**Collaborators on a card** — named group of Avatars.

```html
<pond-stack gap="2">
  <pond-text size="sm" muted>Collaborators</pond-text>
  <pond-avatar-group label="Collaborators">
    <pond-avatar initials="AB" label="Ada Byron"></pond-avatar>
    <pond-avatar initials="CD" label="Chris Diaz"></pond-avatar>
  </pond-avatar-group>
</pond-stack>
```

**Prefer a single Avatar** — one person does not need a group. Prefer Inline of Avatars only when overlap is undesirable and each face stays fully visible.
