Page and section titles. `level` sets h1–h6; visual size defaults from level and can be overridden with `size`.

<ComponentTabs>
  <Fragment slot="examples">
    <PondDemo label="Default sizes by level">
      <div class="pond-demo__stack">

        <pond-heading level="2">h2 · 4xl — section</pond-heading>
        <pond-heading level="3">h3 · 3xl — subsection</pond-heading>
        <pond-heading level="4">h4 · 2xl</pond-heading>
        <pond-heading level="5">h5 · xl</pond-heading>
        <pond-heading level="6">h6 · lg</pond-heading>
      </div>
    </PondDemo>

    <PondDemo label="Level vs size (don’t skip levels for styling)">
      <div class="pond-demo__stack">
        <pond-heading level="2" size="lg">
          h2 at lg — smaller look, same outline level
        </pond-heading>
        <pond-heading level="3" size="4xl">
          h3 at 4xl — emphasize without skipping levels
        </pond-heading>
      </div>
    </PondDemo>
  </Fragment>

  <Fragment slot="code">

```html
<pond-heading level="1">Page title</pond-heading>
<pond-heading level="2">Section</pond-heading>
<pond-heading level="2" size="lg">Same level, smaller type</pond-heading>
```

  </Fragment>

  <Fragment slot="usage">

One `level="1"` per view. **Don't** skip levels for styling — use `size`. See [Typography](/theming/typography/).

  </Fragment>

  <Fragment slot="changelog">

Unreleased — level→scale defaults; optional `size` override.

  </Fragment>

  <Fragment slot="accessibility">

Real heading elements. Outline order comes from `level`, not `size`.

  </Fragment>
